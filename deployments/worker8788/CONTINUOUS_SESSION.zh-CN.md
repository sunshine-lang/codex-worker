# 整单自主会话（8788，ledger/2，2026-11-17）

## 翻译流程

1. 上游照旧提交完整 JSON、翻译 Prompt、项目风格指南和通用规则。
2. Worker 保留原有 100% TM 锁定复用规则，其余条目交给一个 Codex Job。
3. 原始 Prompt 和两份完整指南在首次提交及显式恢复时提供。完整原文、上下文、TB/TM、此前译文和项目笔记随时可读，不预先选择 64 KiB 原文窗口。Codex 自己决定是否分页；`project_read` 的 `count=0` 表示读取剩余全部条目，`char_limit=0` 表示完整返回所选内容。
4. Codex 自行选择阅读范围、翻译顺序和保存分组，可以随时回改早先的译文。每轮 32 条和工具的 32/128 条限制已取消；允许乱序保存。原 32 条/字符预算分区仅用于兼容交付包装，所有分区共享同一个执行任务和会话。
5. 草稿覆盖完整后，写入工具立即返回 `phase=reviewing`，Codex 可在同一 thread、同一个 turn 直接继续整单自检，无须先结束轮次。Codex 查阅当前原文和译文、处理规则提示、纠正需要修改的内容，并确认全部当前版本。写入修改会撤销对应行的检查确认，必须重新读取并检查。
6. 检查完成后，宿主校验完整行号、非空译文、原始字段和产物指纹，再合并发布最终 JSON。原始 segment_id、顺序和其他字段不变。

每次有效写入持久化检查点。模型正常提前结束时，Worker 根据实际进度在原会话要求继续；模型最终说“完成”不能替代译文、当前版本自检和规则提示读取。连续三轮没有实质进度则停止并保留检查点。

原手工流程中的文件阅读、写入和程序检查由项目专属工具承担。模型没有通用 shell、其他项目目录、插件或应用访问权限。官方供应商必要时可使用只读网页搜索查证公开技术术语，优先官方资料；第三方供应商关闭原生网页搜索。禁止整份文档或私有句子搜索。整个项目的译文及重要判断保存在宿主台账中，在会话上下文压缩后仍可重新查询。

## 调用兼容性

- `/v1/tasks`、状态查询、最终 JSON 下载、原 Token 均保留。
- 仍提供 `/v1/tasks/{id}/batches` 和分区结果下载。持续会话模式下，分区直到整单自检完成才成为可下载结果，避免上游缓存后来被回改的草稿。
- 状态增加 `conversation_mode=one_project_one_thread`、`codex_thread_id`、`session_progress`、`self_review_status`。
- `session_progress` 包括草稿条数、已检查条数、回改次数和工具调用数。草稿已齐但仍在检查时，任务状态仍是 running。
- `review_status=not_started` 仍表示上游的独立审校尚未执行。Worker 的自检由同一个 Codex 完成，不能冒充独立审校或保证语言质量。
- 纯 100% TM 整单继续直接复用，不调用模型；其中译文保留原有锁定语义。混合整单可读取、标注锁定 TM 问题，但不自动覆盖它们。

`/v1/ready` 显示服务实际供应商、模型、思考等级，以及 `project_controller_version=ledger/2` 和 `project_turn_scope=whole_remaining_project`。

## 超时、并发与中断

`options.timeout_seconds` 现在对整单 Job 生效，支持 60～7200 秒，未填写仍为 1800。此前 1344 条上游任务配置为 1800 秒，应为新的长整单测试明确设置：

```json
{"timeout_seconds":7200}
```

EXE 的“同时处理的整单数”可选 1～8。每份整单始终占用一个通道，不会把其内容拆到多个独立会话。同一非空项目名的不同请求按接受顺序处理；不同请求不会共享私有译文台账或会话。

模型、思考等级或通道变化仅在服务没有未完成任务时应用。当前配置使用一个全局执行通道，支持官方订阅及可用的第三方 Responses/工具模型。每份整单结束后卸载自己的 thread，确认进程归属与子进程清理后才归还通道。

断连、取消、超时或服务重启不会自动重新调用模型或伪装完成。已写草稿和工具记录保留在该 Job 的控制目录中，最终结果不发布。显式检查点恢复与 Windows 原会话恢复的精确兜底条件见 [恢复说明](RECOVERY.zh-CN.md)。

当前专用 Codex 配置为 `gpt-6.1-sol / medium`，`model_context_window=872000`，`model_auto_compact_token_limit=784800`。压缩由 Codex 执行；原始资料、已保存译文和项目笔记仍可重新读取。配置已写入并重启验证，不表示已经执行达到该阈值的压力测试。

入口仍支持 en → zh / zh-CN，每次最多 10,000 条，并保留文件、消息、日志、输出大小和工具调用保护。这些限制不用于分配每轮翻译工作量。

## 验证依据

测试覆盖同一 thread/同一 turn 翻译与检查、超过 128 条的工具操作、模型自选完整读取或分页、乱序保存和恢复、当前版本检查约束、锁定 TM、越界及跨项目输入拒绝、未完成检查禁止交付。现有任务接口、通道进程隔离、取消和 EXE 配置回退继续回归。详见 [验证记录](VALIDATION.zh-CN.md)。

Worker 为术语、数字、型号、占位符和重复原文译法生成规则疑点，交由 Codex 判断处理。程序强制结果完整性、当前版本自检覆盖和检查提示读取，并非所有疑点必须归零。流程完成不代表每句话语义正确，也不等于第二模型或人工独立审校。
