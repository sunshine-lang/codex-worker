# 整单持续会话（8788）

## 翻译流程

1. 上游照旧提交完整 JSON、翻译 Prompt、项目风格指南和通用规则。
2. Worker 保留原有 100% TM 锁定复用规则，其余条目交给一个 Codex Job。
3. 原始 Prompt 和两份完整指南只在首次提交给这个会话。Codex 可分页读取任意原文、上下文、TB/TM、此前译文及项目笔记，也可检索前后文。
4. Codex 自行选择阅读和保存分组，新译文按原文顺序保存；可以随时回改早先的译文。32 条只作为兼容上游的结果分区，不再触发独立翻译会话。
5. 草稿覆盖完整后，Worker 在同一 thread 发起第二个 turn，要求整单自检。Codex 逐段查阅当前原文和译文、处理规则提示、纠正需要修改的内容，并确认全部当前版本。写入修改会撤销对应行的检查确认，必须重新读取并检查。
6. 检查完成后，宿主校验完整行号、非空译文、原始字段和产物指纹，再合并发布最终 JSON。原始 segment_id、顺序和其他字段不变。

原手工流程中的文件阅读、写入和程序检查由项目专属工具承担。模型没有通用 shell、其他项目目录、插件或应用访问权限。必要时可使用 Codex 的只读网页搜索查证公开技术术语，优先官方资料；禁止整份文档或私有句子搜索。整个项目的译文及重要判断保存在宿主台账中，在会话上下文压缩后仍可重新查询。

## 调用兼容性

- `/v1/tasks`、状态查询、最终 JSON 下载、原 Token 均保留。
- 仍提供 `/v1/tasks/{id}/batches` 和分区结果下载。持续会话模式下，分区直到整单自检完成才成为可下载结果，避免上游缓存后来被回改的草稿。
- 状态增加 `conversation_mode=one_project_one_thread`、`codex_thread_id`、`session_progress`、`self_review_status`。
- `session_progress` 包括草稿条数、已检查条数、回改次数和工具调用数。草稿已齐但仍在检查时，任务状态仍是 running。
- `review_status=not_started` 仍表示上游的独立审校尚未执行。Worker 的自检由同一个 Codex 完成，不能冒充独立审校或保证语言质量。
- 纯 100% TM 整单继续直接复用，不调用模型；其中译文保留原有锁定语义。混合整单可读取、标注锁定 TM 问题，但不自动覆盖它们。

## 超时、并发与中断

`options.timeout_seconds` 现在对整单 Job 生效，支持 60～7200 秒，未填写仍为 1800。此前 1344 条上游任务配置为 1800 秒，应为新的长整单测试明确设置：

```json
{"timeout_seconds":7200}
```

EXE 的“同时处理的整单数”可选 1～8。每份整单始终占用一个通道，不会把其内容拆到多个独立会话。同一非空项目名的不同请求按接受顺序处理；不同请求不会共享私有译文台账或会话。

模型、思考等级或通道变化仅在服务没有未完成任务时应用。原有 ChatGPT 订阅认证和 App Server 进程复用保持。每份整单结束后卸载自己的 thread，确认进程归属与子进程清理后才归还通道。

断连、取消、超时或服务重启不会自动重新调用模型或伪装完成。已写草稿和工具记录保留在该 Job 的控制目录中，最终结果不发布。当前版本不承诺崩溃后自动续跑原会话。

## 验证依据

新增测试覆盖同一 thread 的翻译与检查两阶段、跨分区回改、当前版本检查约束、长文本分页、顺序保存、锁定 TM、越界及跨项目输入拒绝、未完成检查禁止交付。现有任务接口、通道进程隔离、取消和 EXE 配置回退继续回归。

真实质量验收应使用相同来源文档和上游的 1344 条样本。原手工 128 条记录的推理等级为 max，当前运行值保留 high；即使流程一致也不应宣称逐句输出相同或无条件达到同等质量。
