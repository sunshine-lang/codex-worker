# Langflow 接入

本调用节点只需要 Langflow 自带的 Python/HTTP 能力，不安装 Codex CLI 或 Codex SDK。模板在 LFX/Langflow 1.12.6 上编译验证；公司实际版本仍需导入与文件交付验收。

当前模板需要 **Worker 0.2.0 或更新版本**。Langflow 只负责提交文件、查询和下载；直接沿用 Windows 上已有的 Codex 配置，不再填写模型 ID、推理强度或搜索开关。

## 导入与配置

导入 [Codex_Remote_Translation.json](../integrations/langflow/Codex_Remote_Translation.json)。流程包含：

1. 上传原表与翻译资料。
2. 远程 Codex 自主翻译。
3. Chat Output 展示结果。

文件、服务地址和访问令牌均未预填，不包含开发机路径或凭据。若公司禁用自定义 Python 组件，需要管理员按公司规则启用本组件；不通过绕过策略导入。

第二个节点填写：

- **Windows 服务地址**：例如 `https://codex-worker.company.example`；支持已配置的代理路径前缀。
- **高级操作**：日常无需配置，默认“自动运行”。首次提交自动检查连接和就绪状态；已有任务自动续查或下载。高级设置中保留“重新翻译”“取消任务”“检查连接”。
- **服务访问令牌**：填写 Worker 的访问令牌，建议绑定 Langflow 的私密全局变量。这里不是 OpenRouter Key。
- **远端执行时限**：默认 1800 秒，与当前节点等待时间是两个不同概念。
- **本次等待**：默认 900 秒，到时返回任务号，远端任务继续受自己的时限控制。
- **Langflow 对外地址**：默认空，使用同源下载路径；有反向代理路径前缀时填写实际基址。

HTTPS 是默认远程连接方式。回环 HTTP 可用于本地测试；通过受保护网络使用私有 IP 的 HTTP 时，需明确开启“允许受保护私网 HTTP”。不支持在 URL 中携带用户名、密码或查询参数。

临时公网 HTTP 联调可以在高级设置中开启“临时允许明文 HTTP”。这会明文传送令牌和文件，只用于用户明确接受该条件的试跑；通用导入模板默认关闭，正式使用改为 HTTPS 后关闭。粘贴的地址以 `/healthz` 或 `/v1/ready` 结尾时，组件会自动识别服务基址。

## 日常直接运行，高级操作按需使用

| 操作 | 行为 |
| --- | --- |
| 自动运行（默认） | 新资料自动提交；已有任务自动续查；完成后返回文件并明确显示“本次未重新翻译” |
| 重新翻译（高级） | 上次任务结束后新建任务，再次调用 Codex；任务仍在运行时只继续已有任务 |
| 取消任务（高级） | 先请求取消，再读取实际状态；不会把请求已发出误报成已停止 |
| 检查连接（高级） | 单独检查网络、鉴权和执行环境，不上传资料或调用模型；空令牌只查网络 |

首次提交与重新翻译必须提供四份有效文件。自动续查已有任务及取消允许清空全部上传框；部分缺失或失效的绑定会明确报错。上传前检查文件是否存在、文件名是否重复，重名错误指出具体两个字段，不自动改名。一个节点保存该用户、流程、节点和服务地址的当前任务引用；更换服务地址会进入新的引用范围。

已失败、取消或中断的任务不会自动调用模型重跑。确认需要新翻译时，在高级设置选择“重新翻译”，运行后切回“自动运行”以便续查；Langflow 会保留高级操作选择，不会自动复位。原有 API 调用中的“提交或继续”“查询”“重新试跑”“取消”仍兼容，但画布中不再提供这些旧名称。

自动模式只在首次尝试提交新任务前检查 `/healthz` 和 `/v1/ready`。恢复未知提交、查询与下载不依赖就绪检查；即使 Worker 暂时不能接新任务，也可取回已存在的结果。提交被明确拒绝前未创建任务时，可以修正资料再次运行；提交响应丢失则继续保留原编号，不能因为后续报错就假定远端没有任务。

任务引用存放在当前用户的 Langflow 文件存储内，包含提交编号、任务号、输入指纹和已上传产物记录；不包含服务令牌。重启后继续使用原流程、节点、用户和服务地址，才能找回对应引用。不要在任务未结束时清理 Langflow 用户存储。

任务引用写入时短暂加锁，首次提交另有独占锁避免并发上传；提交完成后释放，不占用整个翻译等待期。等待期间可以从另一请求续查或取消同一任务；旧请求不会覆盖后来新任务的引用。若界面不允许同一流程再次运行，将“本次等待”设为 0，先取任务号，再次运行续查。界面的停止操作会尽力请求取消远端任务，仍需查看实际状态确认。

若提交响应丢失，保持四份资料和参数不变，直接再次运行。组件会用原提交编号重试，服务端返回原任务。尚未取得远端编号时，不提供资料就无法找回，节点会明确提示恢复原资料。

若服务明确拒绝首次提交（例如令牌错误、资料不符合约定），会显示具体原因；修正后再次运行，不需要清理缓存。网络中断或不确定的服务错误则保留原提交编号，避免重复创建任务。

从 0.1 升级必须先更新 Windows Worker，再导入本版流程。只删除旧节点的模型字段不能改变旧服务的必填校验；旧 Worker 返回模型参数错误时，新节点会提示升级。旧流程保留作备份，已有终态任务的文件仍由原任务号查询。

## 结果

节点按服务清单下载并验证大小与 SHA-256，再发布到当前用户的 Langflow 存储。已验证并发布的文件可以复用，下载中断不会触发翻译重跑。

`completed` 表示程序交付检查通过，`needs_review` 表示文件可读但有需复核事项；两者均不代表独立语言审校已通过。`failed`、`interrupted`、`cancelled` 会明确显示，并返回可取得的诊断文件。

## 构建导入文件

在已经安装 LFX/Langflow 1.12.6 的开发环境运行：

```bash
python scripts/build_langflow.py
```

脚本使用官方模板编译与连线辅助函数，只生成导入 JSON 和 standalone 源码，不调用服务、不构建执行图、不运行模型。不要把 Langflow 的“验证流程”按钮当成纯静态校验：它可能执行节点。
